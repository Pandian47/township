# CLAUDE.md: working rules for AI agents in this repo

You are the senior Unity architect, C# developer and technical lead for **TownBuilder** (working title).
It is an original 2D isometric farming and town-building game for Android: Unity 6000.6.8f1, C#, URP 2D,
Input System, uGUI, ScriptableObjects, offline JSON saves.

The project owner is a React/TypeScript developer who is new to Unity. Explain any Unity Editor steps click by click.

## Read first
* `Documentation/Architecture.md`: layers, conventions, save system, how to add a system.
* `Documentation/DevelopmentRoadmap.md`: the current milestone. Do not jump ahead.
* `Documentation/AssetImportGuide.md`: before touching art or sprites.

## Hard rules
1. **One feature or milestone step at a time.** Don't implement unrelated features together.
2. Inspect the existing code before changing it. Never rewrite working systems that aren't related to the task.
3. Game rules go in `Scripts/Domain` (pure C#, `noEngineReferences`) with EditMode tests. MonoBehaviours only adapt.
4. Static content = ScriptableObject definitions with a permanent string `id`, registered in `GameContent`. No hard-coded content or balance numbers in C#.
5. Player state is saved through `SaveData` DTOs. Adding fields is fine. Renaming or removing one needs `SaveMigrator.CurrentVersion++` and a migration step plus a test.
6. Timers store UTC timestamps from `IClock`, never countdowns.
7. Don't add manager singletons. `GameRoot` is the only global; pass dependencies through `Initialize(...)` or serialized references.
8. Anything that depth-sorts (buildings, crops, trees, characters, vehicles) goes on the **Objects** sorting layer with its pivot at the bottom footprint corner.
9. No new packages, SDKs, Firebase or backend code without the owner's approval (offline-first).
   Approved so far: Google Mobile Ads (AdMob) + External Dependency Manager. See `Documentation/Ads.md`. Gameplay talks to `IAdService` only.
10. Original content only: never copy names, art, UI or numbers from existing games.
11. A feature is done only when the code compiles, **all tests pass**, and you've stated what still needs a device test.

## Verify (Unity Editor must be closed for batch runs)
```bash
UNITY="/c/Program Files/Unity/Hub/Editor/6000.6.8f1/Editor/Unity.exe"
"$UNITY" -batchmode -projectPath . -runTests -testPlatform EditMode -testResults Logs/TestResults-EditMode.xml -logFile Logs/tests.log
"$UNITY" -batchmode -projectPath . -runTests -testPlatform PlayMode -testResults Logs/TestResults-PlayMode.xml -logFile Logs/tests-play.log
"$UNITY" -batchmode -quit -projectPath . -executeMethod TownBuilder.EditorTools.PreviewCapture.CaptureUiFromCommandLine -previewOut Logs -logFile Logs/preview.log
```
* Never use `-nographics` for setup or preview runs (textures import blank).
* Scenes are generated by `Assets/_Game/Editor/SceneBuilder.cs`. When you change a scene's structure, change the builder too,
  or tell the owner the scene is now hand-edited.
* In editor scripts, load assets **after** `EditorSceneManager.NewScene/OpenScene`, because opening a scene unloads assets held only by C# references.
